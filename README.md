# Case Flow — منصة تدريب طب الأسنان

منصة توزيع الحالات السريرية بين طلاب المرحلة السريرية في المستشفى الجامعي لطب
الأسنان، مبنية حسب وثيقة متطلبات الأعمال (BRD) المرفقة. خمس بوابات مستقلة
بتسجيل دخول منفصل: **السوبر أدمن، السجلات الطبية، طبيب الامتياز، الطالب،
الطبيب المشرف**.

## التقنيات

- **Next.js 16** (App Router, Server Actions, Proxy/middleware) + TypeScript
- **PostgreSQL** عبر **Prisma 7** (باستخدام Driver Adapter `@prisma/adapter-pg`، متوافق مع Neon)
- **Tailwind CSS 4** بهوية بصرية عربية RTL حسب نظام التصميم في القسم 17 من الوثيقة
- جلسات موقّعة بـ JWT (`jose`) في كوكيز httpOnly، بدون مزوّد خارجي للمصادقة
- كلمات المرور مشفّرة بـ `bcryptjs`

## الإعداد المحلي

1. **قاعدة البيانات**: أنشئ قاعدة PostgreSQL (محلياً أو عبر Neon) وضع رابطها في
   `.env` (انسخ `.env.example`):

   ```bash
   cp .env.example .env
   ```

   ```
   DATABASE_URL="postgresql://user:password@host/dbname?sslmode=require"
   SESSION_SECRET="<نص عشوائي طويل، مثال: openssl rand -base64 48>"
   ```

2. **التثبيت والتهيئة**:

   ```bash
   pnpm install
   pnpm run db:migrate   # ينشئ الجداول
   pnpm run db:seed      # يزرع بيانات تجريبية + حسابات تجربة (انظر أدناه)
   pnpm run dev
   ```

3. افتح `http://localhost:3000` وستجد روابط البوابات الخمس.

## حسابات التجربة (بيئة التطوير فقط)

كلمات مرور مؤقتة يُطلب تغييرها عند أول دخول (AUTH-03). **يجب حذف هذه الحسابات
قبل الانتقال للإنتاج** (كما تنص الوثيقة، القسم 5.3).

| البوابة | الرابط | اسم المستخدم | كلمة المرور المؤقتة |
|---|---|---|---|
| السوبر أدمن | `/admin/login` | `sa.admin` | `Adm#2026Temp` |
| السجلات الطبية | `/records/login` | `rec.1001` | `Rec#2026Temp` |
| طبيب الامتياز | `/intern/login` | `int.fahad` | `Int#2026Temp` |
| الطالب | `/student/login` | `443012345` | `Std#2026Temp` |
| الطبيب المشرف | `/supervisor/login` | `sup.2001` | `Sup#2026Temp` |

## ما تم تنفيذه

- **المصادقة (القسم 5)**: 5 بوابات مستقلة بالدور، سياسة كلمة مرور قوية، إجبار
  تغييرها أول دخول، قفل الحساب بعد 5 محاولات فاشلة، انتهاء جلسة تلقائي حسب
  الدور، استعادة كلمة مرور برابط مؤقت، سجل تدقيق لكل محاولة دخول.
- **بوابة السوبر أدمن**: إدارة المستخدمين (بما فيها الاستيراد الجماعي من
  Excel)، التخصصات والإجراءات، العيادات، الفترات الأكاديمية وحصص التخرج،
  مجموعات الإشراف، قوالب الإشعارات، سجل التدقيق، إعدادات النظام وقواعد الحجز.
- **بوابة السجلات**: تسجيل مريض جديد بمنع التكرار (MR-01/MR-02)، البحث في
  الملفات، سجل مكالمات، تصدير بيانات المرضى CSV.
- **دورة حياة الحالة السريرية الكاملة**: طبيب الامتياز ينشئ الحالة ويرسلها
  للاعتماد ← المشرف يعتمد/يعيد للتعديل/يرفض ← تُطرح في بنك الحالات ← الطالب
  يحجزها (مع منع الحجز المتزامن ومطابقة "متطلبك الناقص" وإخفاء بيانات المريض
  قبل الحجز) ← تأكيد الموعد ← توقيع المشرف على بدء العلاج ← رفع خطة العلاج
  وملخص الإنجاز ← تقييم المشرف ← احتساب الحالة في حصة الطالب.
- قواعد العمل القابلة للضبط (القسم 12): الحد الأقصى للحجوزات المفتوحة، مهلة
  تأكيد الموعد (تُعيد الحالة للبنك تلقائياً عند انتهائها)، مهلة الإلغاء.

## ما لم يُنفَّذ بعد (يحتاج قراراً أو مزوّد خدمة خارجي)

- **التحقق الثنائي 2FA وإرسال SMS/بريد فعلي**: البنية جاهزة، لكن لا يوجد
  مزوّد بريد/SMS مُعد بعد. حالياً رابط استعادة كلمة المرور يُعرض مباشرة على
  الشاشة (بيئة تجريبية فقط) بدل إرساله.
- **تخزين الملفات (الأشعة، نماذج الموافقة، خطط العلاج)**: الحقول تقبل روابط
  نصية فقط. يحتاج ربط بخدمة تخزين حقيقية (مثل Vercel Blob) قبل الإنتاج.
- **التقرير الأسبوعي الكامل بصيغة PDF** ولوحة إحصاءات السجلات التفصيلية (تصدير
  CSV للمرضى متاح الآن كبديل مبدئي).
- SSO الجامعي، الربط مع HIS/PACS، نسخة الجوال المخصصة — هذه ضمن "المرحلة 4"
  في الوثيقة أصلاً.

## النشر (Vercel + Neon)

1. أنشئ قاعدة Neon وانسخ رابط الاتصال إلى متغير البيئة `DATABASE_URL` في
   إعدادات مشروع Vercel، وأضف `SESSION_SECRET` عشوائياً.
2. شغّل `pnpm run db:migrate` (أو `prisma migrate deploy` في خطوة البناء) ثم
   `pnpm run db:seed` مرة واحدة لإنشاء البيانات المرجعية الأساسية — **احذف
   حسابات التجربة بعد ذلك أو غيّر كلمات مرورها**.
3. اربط المستودع بمشروع Vercel، فرع `main` (أو الفرع الحالي)، والبناء
   الافتراضي لـ Next.js يعمل دون إعداد إضافي.
